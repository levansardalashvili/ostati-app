# ოსტატების აპი — სრული UI პრომფტი დიზაინერისთვის

## პროდუქტის არსი
Marketplace მობილური აპლიკაცია (iOS + Android), რომელიც აკავშირებს **მომხმარებლებს** (ვისაც სახლის სერვისი სჭირდება — სანტექნიკოსი, ელექტრიკოსი, მღებავი და ა.შ.) **ადგილობრივ ოსტატებთან**. ორი მომხმარებლის ტიპია: **Customer** (ეძებს/პოსტავს მოთხოვნას) და **Provider/ოსტატი** (პასუხობს მოთხოვნებს, იღებს შეკვეთებს). მთელი კომუნიკაცია ხდება აპშივე, ჩატით.

## ზოგადი დიზაინის პრინციპები
- სუფთა, მინიმალისტური, ღია ფონი (თეთრი/ღია-ნაცრისფერი)
- Card-based UI — მრგვალი კუთხეები (12-16px radius), ღია ბორდერები
- ერთი აქცენტის ფერი მთელ აპში (ღილაკები, არჩეული მდგომარეობები, ლინკები)
- სემანტიკური ფერები სტატუსებისთვის: მწვანე (დადასტურებული/ხელმისაწვდომი), ყვითელი/ნარინჯისფერი (მომლოდინე), წითელი (გაუქმება/საშიშროება)
- Bottom navigation, 3 ჩანართი: **Home / ჩატები / პროფილი**
- Mobile-first, ორივე პლატფორმაზე ვიზუალურად თანმიმდევრული

## ნაწილი A — Onboarding (ახალი მომხმარებლის რეგისტრაცია)

**A1. Splash / Welcome ეკრანი**
პირველი, რასაც ხედავს ვინც აპს ხსნის.
- ცენტრში: აპის აიქონი/ლოგო (placeholder — ხელსაწყოს აიქონი), აპის სახელი, ერთი მოკლე tagline
- ორი ღილაკი: **"დაწყება"** (primary/filled) და **"შესვლა"** (secondary/text ლინკი) ვისთვის ვისაც უკვე აქვს ანგარიში

**A2. როლის არჩევის ეკრანი**
- სათაური: "ვინ ხარ?" + ქვეტექსტი რომ ეს განსაზღვრავს შემდეგ ნაბიჯებს
- ორი დიდი, დაჭერადი ბარათი ვერტიკალურად: "მე ვეძებ ოსტატს" (აიქონი: search) და "მე ვარ ოსტატი" (აიქონი: ხელსაწყო)
- დაჭერისას ბარათი ვიზუალურად აღინიშნება არჩეულად (მკვეთრი ბორდერი)
- ქვედა ნაწილში: "გაგრძელება" ღილაკი
- პროგრეს-ინდიკატორი ზედა ნაწილში: "ნაბიჯი 1/3"

**A3. რეგისტრაცია/შესვლა — Email/Password + Google**
- **რეგისტრაციის ეკრანი:** ველები — სახელი, ელ. ფოსტა, პაროლი, პაროლის დადასტურება. ღილაკი "რეგისტრაცია" (primary). ცალკე ღილაკი **"Google-ით გაგრძელება"** (Google-ის ლოგოთი, secondary სტილი)
- **შესვლის ეკრანი:** ველები — ელ. ფოსტა, პაროლი. ლინკი "პაროლი დაგავიწყდათ?" პაროლის ველქვეშ. ღილაკი "შესვლა" (primary), ღილაკი "რეგისტრაცია" (secondary, თუ ანგარიში არ აქვს), ცალკე "Google-ით გაგრძელება"
- **პაროლის აღდგენის ეკრანი:** ელ. ფოსტის ველი, ღილაკი "ბმულის გაგზავნა"
- **Google-ის ანგარიშით პროფილის დასრულება:** თუ Google-ით შემოვიდა პირველად — ეკრანი სადაც Google-იდან წამოღებული ინფო (სახელი, ელ. ფოსტა, ფოტო) უკვე შევსებულია, მომხმარებელი მხოლოდ ადასტურებს/ავსებს დამატებით საჭირო ველებს
- ვალიდაციის შეტყობინებები: "ეს ველი სავალდებულოა", "შეიყვანე სწორი ელ. ფოსტა", "პაროლი უნდა შეიცავდეს მინიმუმ 8 სიმბოლოს", "პაროლები არ ემთხვევა", "ელ. ფოსტა ან პაროლი არასწორია", "ამ ელ. ფოსტით ანგარიში უკვე არსებობს"

**A4. პროფილის შევსება — მხოლოდ Provider-ისთვის**
(Customer-ისთვის ეს ეკრანი მარტივია — მხოლოდ სახელის ველი; დეტალურად არ არის საჭირო რთული ფორმა)
- ველები თანმიმდევრობით: სახელი გვარი (ტექსტი, თუ Google-იდან არ არის უკვე შევსებული), სპეციალობა (dropdown ან multi-select — იხ. კატეგორიების სია ქვემოთ), გამოცდილება წლებში (ტექსტი/რიცხვი), დაფარვის რაიონი (ტექსტი, მაგ. "ვაკე, საბურთალო"), პროფილის ფოტოს ატვირთვა (dashed border box, camera აიქონით)
- ღილაკი "გაგრძელება" ქვემოთ
- პროგრეს-ინდიკატორი: "ნაბიჯი 2/2"

Onboarding-ის დასრულების მერე მომხმარებელი ხვდება შესაბამის Home ეკრანზე (Provider Home ან Customer Home).

**კატეგორიების საწყისი სია** (გაფართოვდება მომავალში):
სანტექნიკოსი, ელექტრიკოსი, მღებავი, ავეჯის აწყობა/რემონტი, კონდიციონერის მონტაჟი/სერვისი

## ნაწილი B — Provider-ის მთავარი გამოცდილება

**B1. Provider Home screen**
- ზედა: მისალმება ("დილა მშვიდობისა") + პატარა ავატარი და სახელი
- სტატუსის toggle ბანერი: "ხელმისაწვდომი ხარ ახალი შეკვეთებისთვის" — მწვანე ფონი როცა ჩართულია, ოსტატს შეუძლია გამორთოს როცა დაკავებულია. **feed მაინც ჩანს გამორთვის დროსაც, უბრალოდ push notification არ მოდის**
- ქვემოთ: "ახალი მოთხოვნები შენს რაიონში" — feed ბარათების სახით. თითო ბარათში: job-ის სათაური, რაიონი, სასურველი დრო, ღილაკი "დაინტერესებული ვარ"
- Bottom navigation

**B2. Job-ის დეტალი + ინტერესის დადასტურება (Provider მხრიდან)**
"დაინტერესებული ვარ"-ზე დაჭერის შემდეგ:
- ზედა: უკან ისარი + job-ის სათაური
- Job-ის დეტალის ბარათი: ლოკაცია (pin აიქონით), დრო (საათის აიქონით), სრული აღწერა
- დადასტურების ბანერი (მწვანე): "გაუგზავნე ინტერესი. ველოდებით მომხმარებლის არჩევანს"
- დაჭერადი ელემენტი: "ჩატის გახსნა" — Provider-ს შეუძლია დაუყოვნებლივ დაიწყოს საუბარი, არ სჭირდება მომხმარებლის არჩევანის მოლოდინი
- ქვედა ნაწილში: "ინტერესის გაუქმება" ღილაკი (წითელი outline, დესტრუქციული მოქმედება)

## ნაწილი C — Customer-ის მთავარი გამოცდილება

**C1. Customer Home / Browse screen**
- ზედა: ორი ფილტრი გვერდიგვერდ:
  - **კატეგორია — მრავალარჩევანი (multi-select)**: მომხმარებელს შეუძლია ერთდროულად რამდენიმე სპეციალობა მონიშნოს (მაგ. სანტექნიკოსი + ელექტრიკოსი ერთდროულად), UI-ში ეს გამოისახება როგორც checkbox-ების სია dropdown/modal-ში, არჩეული კატეგორიები ჩანს პატარა chip/tag-ების სახით ფილტრის ველთან
  - **რაიონი** — dropdown ან ტექსტური ძებნა
- ქვემოთ: ხელმისაწვდომი ოსტატების სია (გაფილტრული არჩეული კატეგორიებით) — თითო ბარათში ავატარი, სახელი, სპეციალობა, გამოცდილება, რეიტინგი (ვარსკვლავი), ღილაკი "მიწერა"
- ცალკე შესვლის წერტილი "მოთხოვნის დადება" (post a job) რეჟიმზე — ტაბი ან floating action button

**C2. Post a Job ფორმა**
- ველები: კატეგორია (dropdown — ერთი კატეგორია job-ზე, რადგან კონკრეტული სამუშაოა), აღწერა (textarea, placeholder-ით), რაიონი (ტექსტი), სასურველი თარიღი და დრო (ცალკე ველები), **სასწრაფოობის ტეგი** (მოკლე არჩევანი: დღეს / 1-2 დღეში / ამ კვირაში / არ მეჩქარება), **ფოტოს ატვირთვა** (არასავალდებულო, 1-3 ფოტო — ეხმარება ოსტატს წინასწარ შეაფასოს სამუშაო), **სავარაუდო ბიუჯეტი** (არასავალდებულო ტექსტური ველი, არა ზუსტი გადახდის მექანიზმი — მხოლოდ ორიენტირისთვის)
- ღილაკი "გამოქვეყნება" (primary, სრული სიგანე)
- შენიშვნა კონფიდენციალურობაზე ფორმის ბოლოში: ტელეფონის ნომერი ავტომატურად არ ჩანს ოსტატებისთვის

**C3. Job-ის დეტალი + დაინტერესებული ოსტატების სია (Customer მხრიდან)**
- ზედა: job-ის ბარათი სტატუსის ბეჯით ("მომლოდინე" — ყვითელი/ნარინჯისფერი), სავარაუდო ბიუჯეტი თუ მითითებულია, ატვირთული ფოტოები თუ არის
- ტექსტი: "დაინტერესდა N ოსტატი"
- სია ოსტატებისა ვინც ინტერესი გამოხატა: ავატარი, სახელი, გამოცდილება, რეიტინგი, ღილაკი "არჩევა" თითოეულთან
- ქვედა შენიშვნა: ჩატის გახსნა შესაძლებელია არჩევამდეც

**C4. ოსტატის არჩევის დადასტურება**
"არჩევა"-ზე დაჭერის მერე:
- Job-ის სტატუსის ბეჯი იცვლება "მომლოდინე" → "დადასტურებულია" (მწვანე)
- ბარათი არჩეული ოსტატით: ავატარი, სახელი, ტექსტი "არჩეულია ამ სამუშაოსთვის"
- ღილაკი "ჩატის გახსნა" (primary, სრული სიგანე)
- საინფორმაციო ბლოკი ქვემოთ: "სამუშაოს დასრულების შემდეგ შეგეკითხებით და შეგეძლება შეაფასო ოსტატი"

## ნაწილი D — Chat

**D1. ჩატების სია (Inbox)**
- სათაური "ჩატები"
- ვერტიკალური სია ყველა აქტიური საუბრისა: ავატარი, სახელი, ბოლო მესიჯის preview (ერთ ხაზად, overflow-ellipsis), დრო/თარიღი მარჯვნივ ზედა კუთხეში
- წაუკითხავი მესიჯის ინდიკატორი — პატარა წერტილი აქცენტის ფერში, მარჯვენა კიდეზე
- დაჭერისას იხსნება ცალკე საუბრის ეკრანი

**D2. საუბრის ეკრანი**
- ზედა: მეორე მხარის ავატარი + სახელი
- ჩატის ბუშტები — მარცხნივ მიღებული მესიჯები (ღია/ნეიტრალური ბექგრაუნდი), მარჯვნივ საკუთარი გაგზავნილი მესიჯები (აქცენტის ფერი)
- ქვედა: ტექსტის ინფუთი + გაგზავნის ღილაკი (send აიქონი) + ცალკე ღილაკი/აიქონი **"ფასის შეთავაზება"**

**D3. ფასის შეთავაზება/დადასტურება (სტრუქტურირებული, არა თავისუფალი ტექსტი)**
- Provider-ს შეუძლია ჩატში გაგზავნოს **სტრუქტურირებული ფასის შეთავაზება** (ცალკე ბარათი ჩვეულებრივი ტექსტის მაგივრად): რიცხვითი ველი (₾) + არასავალდებულო კომენტარი
- ეს ბარათი ჩანს ჩატში გამოყოფილი დიზაინით (არა ჩვეულებრივი მესიჯის ბუშტი) — მაგ. ჩარჩოში, ფასი მსხვილი ფონტით
- Customer-ს უჩნდება ორი ღილაკი ამ ბარათზე: **"დათანხმება"** / **"უარყოფა"**
- დათანხმებისას: ეს ფასი ხდება job-ის **ოფიციალური, დათარიღებული ფასი** — ინახება job-ის ჩანაწერში, ჩანს job-ის დეტალის ეკრანზეც (თარიღი/დრო თან ერთვის)
- უარყოფისას: Provider-ს შეუძლია ახალი შეთავაზების გაგზავნა
- **მიზანი:** ეს ქმნის ფორმალურ ჩანაწერს თავდაპირველ შეთანხმებულ ფასზე — თუ ადგილზე ფასი შეიცვალა, ეს განსხვავება საჩივრებადი/თვალსაჩინოა, თუნდაც გადახდის სისტემის გარეშე

## პროდუქტული წესები, რაც დიზაინს პირდაპირ ეხება

1. **ერთ ანგარიშს ერთი როლი აქვს** — Customer ან Provider, არა ორივე ერთდროულად. UI-ში არ სჭირდება role-switch მექანიზმი თავიდან.
2. **ტელეფონის ნომერი/საკონტაქტო ინფო დაცულია** — მხარეები ერთმანეთს უზიარებენ საკონტაქტო დეტალებს მხოლოდ თუ თავად გადაწყვეტენ ჩატში, ავტომატურად არასდროს ჩანს ერთმანეთისთვის.
3. **ყველა კომუნიკაცია თავიდან in-app ჩატშია**, არა WhatsApp/SMS-ზე გადასვლით (თუმცა ამას ტექნიკურად ვერ ავკრძალავთ, UX ამის წასახალისებლად არის აგებული).
4. **Push notification** იგზავნება: (ა) ახალი მესიჯი ჩატში, (ბ) ახალი ოსტატის ინტერესი job-ზე (Customer-ისთვის). Provider-ს არ მოსდის notification თუ "ხელმისაწვდომობა" გამორთული აქვს.
5. **Job-ის სტატუსების ციკლი:** მომლოდინე → დადასტურებულია → (სამუშაოს დღის შემდეგ) დასრულების დადასტურების მოთხოვნა → დახურული + შეფასება.
6. როცა Customer ირჩევს ერთ Provider-ს, დანარჩენ დაინტერესებულებს job feed-იდან ქრება/დახურულად აღინიშნება.
7. **Browse-ის კატეგორიის ფილტრი მრავალარჩევანია (multi-select)** — Customer-ს შეუძლია ერთდროულად რამდენიმე სპეციალობა მონიშნოს ერთ ძებნაში.
8. **ბიუჯეტის ველი job post-ში მხოლოდ ორიენტირისთვისაა** — არ არის in-app გადახდის მექანიზმი, რეალურ ფასზე მხარეები თანხმდებიან ჩატში. ველი არასავალდებულოა.
9. **ფოტოს ატვირთვა job post-ში არასავალდებულოა** (1-3 ფოტო) — ეხმარება ოსტატს წინასწარ გაიგოს სამუშაოს მოცულობა.

10. **ფასის შეთავაზება ჩატში სტრუქტურირებულია, არა თავისუფალი ტექსტი** — Provider აგზავნის კონკრეტულ რიცხვს ცალკე ბარათის სახით, Customer ფორმალურად ეთანხმება/უარყოფს. დათანხმებული ფასი ინახება job-ის ჩანაწერში დათარიღებული.
11. **Job-ის დასრულებისას შეფასების ფორმაში სავალდებულო კითხვა: "ფასი შეესაბამებოდა შეთანხმებულს?"** (კი/არა) — უარყოფითი პასუხი აისახება Provider-ის პროფილზე (მაგ. ცალკე ინდიკატორად) და ეხმარება მომავალ მომხმარებლებს ენდონ პლატფორმას.

## ტექნიკური შენიშვნა — Authentication Setup (დეველოპმენტისთვის, არა დიზაინისთვის)

Email/Password + Google Sign-In-ის იმპლემენტაციისთვის, დამატებით საჭირო იქნება (Claude Code-თან ერთად, პროექტის დაწყებისას):

- **Firebase Console-ში Authentication-ში ჩართვა:** Email/Password provider და Google provider
- **Google Cloud Console-ში OAuth Client ID-ების შექმნა** — ცალ-ცალკე Android-ისთვის და iOS-ისთვის (SHA-1 fingerprint-ი Android-ისთვის, Bundle ID iOS-ისთვის)
- **`@react-native-google-signin/google-signin` პაკეტის დამატება და კონფიგურაცია** პროექტში
- ეს ყველაფერი კეთდება React Native Firebase-ის (`@react-native-firebase/auth`) გვერდით, არა მის მაგივრად

ეს ნაბიჯები Claude Code-ში კონკრეტულად გავივლით პროექტის setup-ის ეტაპზე — არ საჭიროებს ახლა ცალკე მოქმედებას შენგან.
